# 0.4.0 验收：装插件时也提示「功能重叠」

## 出发点

装前体检原先只答「会不会撞」：同名工具、同名服务、同一行 patch、同一段 skill。它不答用户装之前真正在问的那句：「我已经有了干这活的插件，再装一个会不会互相干扰」。

这类情况很少抛错，而是互相打架：两个包都盯同一份输入、都写同一类状态、都往同一个界面位置放控件；真出问题时日志里躺着两个嫌疑人。0.4.0 把它单独报出来。

## 做了什么

- 新增 `install-check/lib/overlap.mjs`：只用 `scanPackage` 已经读到的签名，不读文件、不联网、不起定时器。
  - 能力词：把工具名按 `_`、`.`、大小写拆词，去掉 `list`/`get`/`save` 这类只说怎么实现、不说干什么的词，保留 `memory`、`browser`、`search` 一类领域词。
  - 同一处界面（两个包往同一个 slot 放东西）排在前面；同一类能力（共享领域词）随后；最多 3 条。
  - 只给建议文案，不改任何状态、不拦安装。
- `checkInstall` / `enabledCheck` 都接上：装包和启用都提示。
- 新增 `config.overlapCheck`（默认开）：只关这块建议，`installCheck` 的其余检查与 `mode` 语义不变。
- 文案说清后果与动作：「两套同时开容易抢同一份输入输出，效果变差，真出问题也分不清是谁；装之前先决定要不要留一个」。

## 名字之后，再读实现

功能重叠靠领域词，是猜。装之前再读一遍候选源码，只报会直接带走宿主或让激活失败的写法：顶层 `throw`、顶层裸 `await`、`process.exit`、接管退出信号、patch 引用未声明的包、同 id 重复 etc. 规则库与 `cli.mjs check` 完全同一套（`lib/judge.mjs`），所以备注里的规则号和行号与手工预检一致；最多两条，其余只计数。

- 静态读文本，不执行插件、不联网、不写盘；读不到就静默。
- 跑的是两层规则：随包发的种子规则（所有人一样）+ 这台机器从自己崩溃日志里学到的规则（`lifeguard/rules.json`）。日志不同，学到的规则就不同；在谁机器上学到，就守在谁的安装动作前。学到的规则读坏了只会少报，不会挡住种子规则。
- 运行期才出现的竞态、两个插件抢同一份状态，不在本版能力内，文案不承诺。
- 开关 `config.implCheck`（默认开），与 `overlapCheck` 互不影响。

## 用例

`test/impl.test.mjs`（6 条）：致命写法带行号、顶层 throw、干净包不报、最多两条并计数、本机学到的规则也参与、读不到不抛。
`test/overlap.test.mjs`（9 条）：拆词与去噪、异名同功能、同 slot 排序、无关包不报、不与自己比、最多 3 条、非插件不比。
`test/install-check.test.mjs` 增 4 条：启用时给出重叠建议；`overlap: false` 时该建议消失而其他检查仍在；安装时点名会带走宿主的候选；`impl: false` 时静默。原「同名工具消失后应静默」的用例改为断言更软的那条建议。

全量 `node --test test/*.test.mjs`：186 通过 / 0 失败。`node cli.mjs check .`：预检通过。

## 边界

- 这是猜，不是判定：领域词重叠可能只是同类不同用，所以只作建议、可关。
- 只在装/启用的那一刻看一眼，不常驻监控；插件之间后续行为差异（谁改谁的状态）不在本版范围。
- 静态读源码，读不到就静默跳过，永不阻断安装。
